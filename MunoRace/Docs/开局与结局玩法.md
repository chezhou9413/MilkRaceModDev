# 缪诺开局与结局

## 开局选择

| 开局 | 人物 | 初始关系 | 核心玩法 |
| --- | --- | --- | --- |
| 缪诺开拓队 | 三名成年缪诺女性 | 好感 80，同盟 | 带充足物资开拓 |
| 一牛四男：生存挑战 | 一名成年缪诺女性、四名成年男性人类 | 好感 0，中立 | 少量物资，通过录像换取补给 |
| 缪诺叛逃者 | 一名成年缪诺女性、一名成年人类同伴，同伴性别随机 | 好感 -100，敌对 | 宽限期后遭遇持续追击 |

人物在原版准备页面生成，可以重随机；种族框架的随机种族重选不会改变已配置的位置请求。生存挑战与叛逃者使用低装备预算的缪诺人物类型。所有开局都禁止额外随机随身物资，具体初始物品在剧本 XML 中配置。

三种开局要求世界中存在缪诺聚落。选中可行动的殖民者，使用“联络缪诺聚落”按钮即可联系，不要求先建通讯台。普通通讯台联络缪诺时也会进入统一服务菜单。

## 摄像机与录像兑换

1. 生存挑战开局提供一台“生存挑战摄像机”，需要手动穿戴。
2. 摄像机使用独立挂具层，不占武器栏，也不排斥普通腰带。人类与缪诺均可穿戴。
3. 穿戴者每隔 0.1～0.25 天可拍摄一段：12 格内须有另一名清醒、未倒地的自由殖民者，并具有直线视野，任务临时访客不作为拍摄对象。
4. 自动拍摄会暂停可中断的日常工作，并在结束后恢复可挂起的工作。它不抢占玩家命令、搬运、忙碌战斗、不可中断工作和紧急饥饿或休息需求。
5. 摄像机穿戴后自动运行，只提供“上传录像带”按钮，没有拍摄开关和手动指定对象功能。镜头随人物四个朝向转动，佩戴和取景时均朝向人物前方。
6. 到达机位后执行举机、持续取景和收机动作，默认共 300 游戏刻，即正常速度约 5 秒。人物持续朝向对象，摄像机随人物朝向和身体渲染节点运动，取景时有轻微手持晃动。
7. 录制阶段显示红色提示灯及对象上方进度条，收机前播放闪光与快门声，完整结束后显示“片段已记录”。失去视野、对象离开或睡眠、摄影者征召、倒地、失去操作能力等情况会中断拍摄，不增加片段。
8. 每 4 个完整片段产生一份实体录像带，放在穿戴者附近。记录的是游戏物品，不生成实际视频文件。
9. 点击摄像机的“上传录像带”按钮，或在聚落服务菜单选择“上交录像带”。每份录像抽取一次奖励，支持批量提交，单次最多 50 份。

上交扫描当前地图上已显露、未禁用的录像带，不扫描远行队、人物背包或其他容器。物资成功进入投放流程后才扣除录像带。聚落敌对、失效或被消灭时不能兑换。

奖励池包含生存包装食品、工业药品、钢铁、工业零部件和白银。摄像机可在机械加工台制造，需要机械加工研究、工艺 3、钢铁 40 和工业零部件 2。

摄像机使用用户提供的四张图片：`MnuoCamera.png` 用作地面和操作图标，`MnuoCamera_south.png`、`MnuoCamera_east.png`、`MnuoCamera_north.png` 用作人物各朝向图，西向由东向镜像。原文件逐字节复制到 `Textures/Apparel/MunoCamera`，未裁剪、染色或缩放图片文件。人物摄像机使用独立渲染节点，不要求不同体型的服装贴图。拍摄期间停用该人物的远距静态贴图缓存，保留其他人物动画。录像带仍使用原版数据设备图标。

快门音效位于 `Sounds/Camera/MunoCameraShutter.wav`，由 `Tools/Assets/Build-CameraShutter.ps1` 合成双段机械脉冲，不依赖外部音频。录制提示灯和闪光使用原版发光纹理及本模组独立 Fleck 定义。

## 叛逃追击

- 首次追击在开局 5 天后到期，后续间隔 5～8 天。
- 追击绑定最初的两名逃亡者，选择仍属于玩家的逃亡者所在地图。
- 采用缪诺派系的原版边缘步入袭击，进攻策略为立即攻击。
- 点数基于当前地图威胁点数，每完成一波增加 15% 系数，最终限制在 100～800 点。
- 逃亡者在远行队或没有地图的位置时，不生成地图袭击；保留到期状态，进入地图后继续追踪。不额外生成世界地图伏击。
- 达成非敌对关系、原始逃亡者全部离开玩家队伍、聚落失去活动能力，或达成融入结局时永久停止本次追击。
- 这是剧本明确安排的持续袭击，不依赖故事讲述者随机抽中缪诺，也不受随机暴力任务开关控制。

敌对期间常规聚落事务和录像兑换暂停，但可以提出融入申请。其他已有外交渠道带来的和平可以撤销追击。

## 融入缪诺结局

在“联络缪诺聚落”菜单选择“申请融入缪诺聚落”。

### 人员范围

- 统计所有地图、远行队、运输容器和重力飞船中的非缪诺正式殖民者与奴隶，包含儿童。
- 不统计囚犯、任务临时访客、动物、机械体和死者。
- 至少保留一名属于玩家的缪诺正式成员。
- 从当前联络者所在地图接人；其他地图的成员可以分批交付。容器内人员需要先回到地图，不能仅凭当前地图人数判断结局。

### 交付流程

申请会显示本次人员名单和其他位置的剩余人数。确认后调用现有接收穿梭机，装载指定成员；本流程不发人口交换奖励。所有成员完成实际离场后，才记录交付。

已有据点人口交换与普通穿梭机交换也会记录符合范围的正式成员交付。如果这些交换已经交付了全部非缪诺成员，再主动申请融入即可确认结局。

只有一次实际交付恰好清空了全局剩余名单，才取得结局资格。至少需要一名正式成员的成功交付记录；纯缪诺开局不会直接达成结局。仍有人未交付时，即使随后死亡或被驱逐，也不会自动取得资格。取得资格后有新的非缪诺正式成员加入，会撤销资格，需要再次交付。

### 时间与结束方式

- 以最后一批人员实际离开地图或完成据点移交的时刻结算。
- 开局未满 7 天：开局跑路结局。
- 开局满 7 天及以后：跑路结局。
- 玩家稍后点击确认不会改变已经记录的交付时间。
- 每局只达成一次。显示结局文字并写入档案，剩余缪诺留在当前地图，可继续经营或返回主菜单。

## 配置与代码位置

| 位置 | 职责 |
| --- | --- |
| `1.6/Defs/Scenarios` | 三种剧本、人员配置、初始物资 |
| `1.6/Defs/MunoStory/Muno_StoryConfig.xml` | 摄像间隔、每段拍摄时长、产量、追击间隔、点数、结局时间边界 |

| `Source/MunoRaceLib/MunoRecording` | 摄像进度、实体录像与兑换 |
| `Source/MunoRaceLib/MunoRecording/Jobs` | 拍摄对象与机位选择、任务阶段、中断和完整片段提交 |
| `Source/MunoRaceLib/MunoRecording/Visuals` | 摄像机人物节点、举机收机、渲染缓存控制与视觉音频反馈 |

| `Source/MunoRaceLib/MunoEndings` | 结局申请、交付记录及实际离场回调 |

这些持久化字段用于本功能的正常保存和读档，不提供旧会话迁移逻辑。

## 编译

使用本机 MSBuild，配置 Debug，指定 `/p:LangVersion=latest`。输出写入本项目 `1.6/Assemblies/MunoRaceLib.dll`，没有启动游戏或执行运行时测试。

项目已有的 `HarmonyMod` 引用是 AMD64，当前工程目标是 AnyCPU，编译器仍会报告 MSB3270 架构警告。
